# 網頁平台架構（2026-10-26 討論稿）

> 狀態：**討論稿，待使用者決定**。依據：`docs/preface.md` 第 III 節行動目標（第 3 版）、`docs/research-question.md`、`docs/project-plan.md`。

## 一、從行動目標推出的設計原則

| 行動目標裡的句子 | 對架構的要求 |
|---|---|
| 「數據是關鍵的溝通工具，也是建立共識的基礎」 | 每筆資料都要**可追溯**：來源、授權、驗證狀態、最後確認日期。不可信的資料無法建立共識（CASAS2020：資料庫裡有大量不存在的公司） |
| 「臺北市社區層級的資源資料庫」 | 全市一致的資料模型和自動化管線；以村里或最小統計區作為統計單元 |
| 「物質和非物質性的資源」 | 資料模型要同時容納物、工具、空間、技能、知識，以及物質的流動 |
| 「將數據轉化為知識」 | 平台不能只是點位地圖，要有從資料到知識的層次（見第三節） |
| 「以台大社區堆肥據點為示範點……作為後續資料填充的範本」 | 把示範點做成**可複製的「據點範本」**：需求清單、範圍、驗證資料的規格 |
| 「開放全台北市不同的社區行動者更新此資料庫」 | 貢獻與審核機制；第一階段先用低門檻工具，第二階段再加帳號和後端 |
| 「資源媒合與溝通的工具」 | 需求與供給（Intent）的資料結構從第一天就預留 |
| 「支持台北都市再工業化的資料基礎」 | 開放格式、開放授權、和國際標準相容（OSM、Valueflows），並提供資料下載和 API |

另外兩條來自文獻的原則：
- **可見度要分級**：讓資源被看見可能帶來取締或仕紳化（CHIEN2018、ORBAN2021）；個人技能資料受個資法保護（CLAUDE.md 工作慣例）。
- **新舊並陳**：平台不能只呈現創客和循環新創，要讓老店家和師傅同樣被看見（ORBAN2021）。

## 二、整體架構：四層

```
┌─────────────────────────────────────────────────────────┐
│ 4. 呈現層（靜態網站）                                     │
│    地圖｜據點頁｜區域概況｜需求清單｜物質流｜資料下載     │
├─────────────────────────────────────────────────────────┤
│ 3. 發布層                                                 │
│    GeoJSON / CSV（下載）＋ PMTiles（地圖圖磚）＋ 資料字典 │
├─────────────────────────────────────────────────────────┤
│ 2. 資料層（核心資料模型，存在 Git repo）                  │
│    據點｜資源｜行動者｜需求與供給｜流動事件｜區域統計     │
├─────────────────────────────────────────────────────────┤
│ 1. 來源層（三個層級）                                     │
│    T1 全市開放資料（自動）                                │
│    T2 示範點現地資料（走讀、訪談、事件紀錄）              │
│    T3 社群貢獻（表單 → 審核 → 合併）                      │
└─────────────────────────────────────────────────────────┘
```

**為什麼第一階段不需要後端資料庫**：
- 兩個月、小團隊，靜態網站最省維護成本，可以免費放在 GitHub Pages，也不怕沒人付伺服器費用就停擺。
- 資料放在 Git，每次修改都有歷史紀錄，本身就是「可追溯」的。
- 開源專案的別人可以直接 fork 整個 repo 來複製到其他城市。
- 等社群貢獻量大到需要即時編輯時，再加後端（第六節）。

## 三、從資料到智慧：平台的四個層次

參考 HILL2020 p.227 的「從資料到智慧」：

| 層次 | 在平台上是什麼 | 例子 |
|---|---|---|
| **資料**（data） | 原始圖層、可下載的資料集 | 五金行點位、各里人口、使用分區 |
| **資訊**（information） | 地圖、指標、區域概況 | 各里的製造據點密度、高齡指數、業態多樣性 |
| **知識**（knowledge） | 針對某個據點或某個問題的分析 | 「堆肥站的需求清單裡，有 60% 在騎車 15 分鐘內找得到；木作技能和運輸是缺口」 |
| **智慧**（wisdom） | 引導行動 | 需求與供給版、工作坊紀錄、政策建議 |

這也對應三個研究子問題：資訊層回答 Q2（分布），知識層回答 Q1（構成和缺口），智慧層和試點回答 Q3（治理）。

## 四、核心資料模型

### 六種實體

| 實體 | 說明 | 主要欄位（草案） | 對應標準 |
|---|---|---|---|
| **據點**（Node） | 有實際位置的地點：店家、工廠、維修中心、堆肥站、創客空間、閒置空間 | id、名稱、類型、座標、地址、營業項目或 OSM 標籤、開放時間 | OSM `shop=*`、`craft=*`、`amenity=*` |
| **資源**（Resource） | 據點擁有或能提供的東西，分五類：物料、工具、空間、技能、知識 | id、所屬據點、類別、名稱、數量或描述、可借／可售／可贈 | Valueflows `EconomicResource` |
| **行動者**（Agent） | 組織，例如社團、NGO、店家、學校單位。**個人不單獨建檔** | id、名稱、類型、聯絡方式（可選、分級） | Valueflows `Agent` |
| **需求與供給**（Intent） | 「需要 4 片棧板」「有木屑可以給」 | id、行動者、需要或提供、資源類別、數量、期限、狀態 | Valueflows `Intent` |
| **流動事件**（Event） | 實際發生的物質、工具或人力流動 | id、時間、提供者、接收者、資源、數量、起訖地點、距離、成本 | Valueflows `EconomicEvent` |
| **區域統計**（Area） | 村里或最小統計區的統計資料 | 區域代碼、人口、年齡結構、使用分區比例、指標值 | — |

### 每筆資料都要有的「後設欄位」
| 欄位 | 用途 | 值的例子 |
|---|---|---|
| `source` | 資料來源 | `gcis_f206010`、`osm`、`field_2026-11-14` |
| `license` | 授權 | `OGDL-1.0`、`ODbL-1.0`、`CC-BY-4.0` |
| `verification` | 驗證等級 | `0 未驗證`、`1 開放資料`、`2 現地確認`、`3 當事人確認` |
| `verified_at` | 最後確認日期 | `2026-11-14` |
| `visibility` | 可見度 | `public`、`aggregate`（只在區域統計中出現）、`private`（只給團隊） |

> **驗證等級**是對 CASAS2020 發現（將近一半廠商只有現場才找得到）的回應，也讓地圖可以把「已驗證」和「未驗證」的點分開呈現。
> **可見度**處理個資和仕紳化的風險：師傅個人一律 `aggregate`；未登記工廠預設 `private`。

### 據點範本（示範點如何變成可複製的模板）
一個社區據點，例如堆肥站，用一個設定檔描述：
```yaml
node: ntu-compost
name: 台大社區堆肥站
practice: composting        # 實踐類型
range:
  mode: bicycle
  minutes: 15               # 騎車 15 分鐘等時圈
bill_of_needs:              # 需求清單，對應 project-plan 軸 1
  - category: material
    item: 木材（耐腐）
  - category: skill
    item: 木作
  - category: transport
    item: 貨運自行車
  # ...
```
平台根據這個設定，自動算出範圍內的資源有哪些、哪些需求可以滿足、哪些是缺口。**其他社區據點，例如社區園圃或修繕咖啡館，只要寫一份自己的設定檔，就能得到同樣的分析。** 這就是行動目標裡說的「後續資料填充的範本」。

## 五、資料來源：三個層級

| 層級 | 內容 | 取得方式 | 第一階段範圍 |
|---|---|---|---|
| **T1 全市開放資料** | 商業登記（營業項目代碼）、工廠清冊、OSM、人口（SEGIS）、使用分區、都更範圍、資源回收站、廚餘統計 | 腳本自動下載、清理、地理編碼，每月可重跑 | 台北市全市 |
| **T2 示範點現地資料** | 走讀驗證的店家、師傅訪談（彙整）、維修中心和林產館的資源、試點的流動事件 | 野外調查表單（例如 KoboToolbox）加上人工整理 | 堆肥站騎車 15 分鐘範圍 |
| **T3 社群貢獻** | 新的據點、資源、需求與供給 | 線上表單，經審核後合併 | 第一階段只開放需求與供給 |

**資料缺口的處理**：「廢棄物流向」在鄰里尺度可能只有區級或全市統計（待查核），所以 T1 用區級統計，T2 用試點自己記錄的流動事件補充。

## 七之一、介面設計（2026-10-26 討論稿）

以地圖為主要介面（使用者決定）。桌面版：上方是搜尋列和模式切換，中間是地圖，右側是詳細資訊面板，下方是鄰里概況；手機版把面板改成底部抽屜。

### 三種模式
| 模式 | 使用者想做什麼 | 地圖上顯示什麼 | 對應研究子問題 |
|---|---|---|---|
| **探索鄰里**（預設） | 了解某個地方的人口和資源現況 | 村里以人口指標著色，疊上據點標記；點選村里，下方顯示鄰里概況 | Q2 分布 |
| **找資源** | 「我需要木材，附近哪裡有？」 | 只亮起擁有該資源的據點，可以從任一據點畫出騎車或步行的等時圈 | 媒合 |
| **示範點** | 看堆肥站的需求清單和缺口 | 需求清單的每一項標示可得或缺口；點選某項，地圖顯示供應者並畫出連線；另有物質流 Sankey 圖 | Q1 構成、Q3 治理 |

### 鄰里人口的呈現
- **地圖底色**：村里分級著色（choropleth），使用者可以切換指標，例如人口密度、65 歲以上比例、扶養比、製造與供應據點密度。一次只顯示一個指標，用單色漸層，避免地圖太花。
- **點選村里後的概況卡**：
  - 人口、65 歲以上比例（附全市平均作為比較）、製造與供應據點數、已驗證比例；
  - 第二層展開：人口金字塔、據點類別組成、使用分區比例。
- **資料來源**：內政部戶政司的村里統計、財政部的綜所稅村里統計，詳見 `docs/data-sources.md`。

### 圖層清單（2026-10-26 使用者補充：性別、教育程度、收入、土地使用、交通）

**人口與社經**（村里著色，一次一個指標）：
| 群組 | 指標 | 呈現 |
|---|---|---|
| 人口結構 | 人口數、人口密度、65 歲以上比例、扶養比 | 著色；概況卡顯示人口金字塔 |
| 性別 | 性別比；可和年齡、教育交叉 | 著色；人口金字塔分男女 |
| 教育程度 | 大專以上比例、高中職比例 | 著色；概況卡顯示各學歷占比 |
| 收入 | 綜合所得**中位數**；第一、三分位數之差（所得分散程度） | 著色；概況卡附全市中位數比較 |
| 資源 | 製造與供應據點密度、業態多樣性 | 著色 |

**空間**（疊加圖層，可同時開啟）：
| 群組 | 圖層 | 呈現 |
|---|---|---|
| 土地使用 | 都市計畫使用分區（住宅、商業、工業等） | 半透明面，預設關閉；開啟時人口著色自動關閉，避免顏色衝突 |
| 土地使用 | 都更範圍、工業區變更範圍 | 斜線或外框 |
| 交通 | 捷運站、公車站、YouBike 站 | 小圖示，縮放到街區尺度才顯示 |
| 交通 | 自行車道 | 線 |
| 交通 | 騎車或步行等時圈 | 虛線範圍 |

**設計原則**：
- 一次只開一個著色圖層（人口指標**或**使用分區），點狀和線狀圖層可以多個同時開。
- 每個指標旁都有「i」說明，寫出資料來源、年度和限制，例如「按戶籍統計，不含未遷戶籍的學生」。

### 據點資源的呈現（建議）
**地圖上：標記要簡單**
- 用**形狀和顏色**區分據點類型，最多四類：製造（例如鐵工、木工）、供應（例如五金行、木材行）、支援設施（例如維修中心、回收站、創客空間）、社區據點（例如堆肥站、社區園圃）。
- 用**實心和空心**區分驗證狀態：實心是現地確認過的，空心是只有開放資料。這樣使用者一眼就知道哪些點可信。
- 地圖上不放資源細節，避免太擠。

**點開據點後：資源卡**
- **標頭**：名稱、類型、開業年數（如果有），以及驗證標章和確認日期。
- **資源依五類分組顯示成標籤**：物料、工具、空間、技能與知識。
- **每個資源標籤附上取得方式**：售、借、贈、付費代工、交換。這是媒合時最實用的資訊。
- **「他們需要」**：用虛線框的標籤表示。讓每個據點同時是供給者和需求者，平台就從名錄變成媒合工具。
- **底部**：資料來源和授權，以小字呈現。
- **個人資訊**：師傅個人不出現在卡片上，技能掛在組織或據點底下；聯絡方式依可見度設定決定要不要顯示。

**「新」與「舊」的並陳**（回應 ORBAN2021）
- 老店家和新興的社區據點用同樣的視覺份量呈現，不讓創客空間或循環新創特別醒目。
- 資源卡顯示「開業年數」，讓長期扎根的店家被看見。

### 待討論
- 指標著色要用村里還是最小統計區？村里比較好懂，最小統計區比較細。
- 「找資源」模式的等時圈要即時計算（需要路網服務），還是預先算好幾個據點？
- 要不要讓使用者切換「只看已驗證」？

## 七、網站頁面（第一階段）

1. **地圖首頁**：
   - 可切換的圖層：製造據點、供應據點、支援設施、空間壓力、人口；
   - 用顏色或圖示區分驗證等級；
   - 「新」與「舊」製造活動並陳。
2. **據點頁**：單一據點的資源、需求與供給、驗證狀態和來源。
3. **示範點頁（堆肥站）**：
   - 需求清單的可得性分析，標出哪些找得到、哪些是缺口；
   - 騎車等時圈；
   - 試點的物質流 Sankey 圖和工作坊紀錄。
4. **區域概況**：以村里或統計區為單位的指標儀表板。
5. **需求與供給版**：目前的需要和可提供的東西（第一版用表單收集，人工整理後上架）。
6. **關於與方法**：研究問題、資料來源、驗證方式、授權、隱私原則、如何貢獻。
7. **資料下載**：各資料集的 CSV、GeoJSON 和資料字典。

├── CLAUDE.md
